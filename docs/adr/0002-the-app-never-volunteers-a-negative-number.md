# The app never volunteers a negative number

Two people clean this flat and neither needs an app that opens by listing what they have not done. Any figure with a denominator — `23/61` — reads as "38 things you failed to do", so the primary flow contains no denominators, no outstanding counts and no unprompted lateness. Counters start at zero each Run and only ever go up.

This is a product constraint, not a styling preference. It is recorded because the code will look under-featured without it: a future reader will find a progress bar conspicuously missing and be tempted to add one.

## What this means in practice

- **Home is forward-looking**: `Start cleaning`, the Routines, and at most a past-tense trophy (`Last time: 23 tasks, 1 h 40 min`). No due counts, no "last cleaned 12 days ago", no freshness gauge.
- **An open Run shows a count-up only** — `Cleaning in progress · 12 done`. Never `12/38`.
- **The completion screen uses absolute numbers**, never a fraction or a comparison with what was available.
- **Statistics live behind a deliberately opened tab.** The same numbers feel like insight when sought and like judgement when pushed.
- **Merely Due is styled neutrally.** Visual escalation only past 2× cadence, so a normal Saturday is not a wall of red.
- **No push notifications, and no Google Calendar.** The app has no proactive channel at all.

## Settled, do not re-open

- **Google Calendar integration** — considered as the one acceptable proactive surface, on the grounds that a calendar entry reads as a plan you made rather than a debt being called in. Deferred for lack of a clear purpose, not rejected on principle. Cadence data is recorded, so it can be added later without migration.
